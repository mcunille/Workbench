# H5 narrated walkthrough

Narration: Microsoft Zira (synthetic voice).

## 00:00:00 — Put a record aside

Archiving puts a record aside without changing its identity or description. Its existing link remains useful. This demonstration uses synthetic collection data and a real disposable database.

## 00:00:14 — Decide before submitting

Archive record opens a confirmation naming this record. It explains that browsing and search will no longer show it, and restoring it to browsing is currently unavailable. Cancel closes the confirmation without sending an archive request.

## 00:00:31 — Review a concurrent correction

Another signed-in session corrects the name while this confirmation is open. The old confirmation cannot archive the changed record. Workbench loads the current saved details and requires a new decision.

## 00:00:45 — Recover an uncertain outcome

After a new confirmation, the archive commits, but we deliberately interrupt its response. Workbench says the outcome could not be confirmed. Changing appearance preserves the recovery controls. Retry sends the same checked version.

## 00:01:03 — Read the saved record

The retry discovers the current archived state. The record is read-only at the same address. Archiving has preserved its description and storage location. This state does not claim which request archived it.

## 00:01:19 — Keep everyday browsing clear

The archived record no longer appears in collection search, in either Grid or List. Returning through its saved link still shows the archived record. Archiving does not delete the record or assert that the physical item was sold or disposed of.
